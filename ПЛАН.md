# План реализации: Песочница анимаций интерфейса

> Документ-инструкция для исполнителя (модели/разработчика). Читать сверху вниз, выполнять фазы строго по порядку.
> Каждая фаза заканчивается коммитом. Не начинай следующую фазу, пока не выполнены все критерии приёмки текущей.

---

## 0. Правила работы

1. **Никаких фреймворков, сборщиков, npm.** Только `index.html`, `.css`, `.js`. Скрипты подключаются обычными `<script src>` по порядку (без ES-модулей), чтобы проект открывался двойным кликом по `index.html` через `file://`.
2. **Никаких CDN и внешних запросов.** Шрифт Inter — системный стек с фолбэком (см. §Приложение A). Иконки — инлайновые `<svg>`.
3. **Ни одного «магического» значения в CSS.** Все цвета, отступы, скругления, тени, типографика — только через CSS-переменные из `css/tokens.css`. Если нужного токена нет — это сигнал, что решение нестандартное: остановись и спроси.
4. **Макет — источник истины.** Figma-файл: `<figma-file-key>`, секция `1:5982` «Песочница B2B». Node id всех частей — в Приложении G. Перед вёрсткой каждого блока вызывай `get_design_context` на его node id, после вёрстки — `get_screenshot` и сравнивай глазами.
5. **Не рефактори то, что уже принято.** Каждая фаза дополняет предыдущую, не переписывает.
6. **Git — после каждой фазы.** Сообщения коммитов заданы в плане. Если фаза сломала предыдущую — откатывайся (`git revert` / `git checkout <файл>`), а не «чини поверх».
7. **Комментарии в коде — по-русски, кратко**, только там, где неочевидно (движок анимаций, режимы тулбара).
8. **Адаптив не делаем и не проверяем.** Песочница — инструмент для десктопа. Вёрстка резиновая (как и макеты в Figma: при смене ширины тянется первая колонка таблицы и контентная область, остальное фиксировано), но **никаких медиазапросов, брейкпоинтов и мобильных проверок**. Не трать время и токены на прогон по ширинам — достаточно, что ничего не ломается при обычном изменении окна на десктопе.

## 1. Что делаем

Одностраничная веб-песочница для настройки анимаций интерфейса.

Экран состоит из двух частей:

- **Тулбар** (сверху, фиксированный, всегда виден) — это служебный UI песочницы, он НЕ является частью макета и не обязан следовать ДС (но должен быть аккуратным и нейтральным, чтобы не спорить с макетом).
- **Макет** (под тулбаром) — точная вёрстка B2B-экрана: шапка, сайдбар, сабхедер, таблица классов с раскрывающимися строками, сайдпейдж редактирования ученика, диалог сохранения.

Два режима работы, переключаются в тулбаре:

- **Режим «Выбор»** — клики по макету не выполняют его действия, а выбирают элемент. У выбранного элемента в тулбаре открывается панель настройки анимации.
- **Режим «Просмотр»** — макет работает как обычный интерфейс: строки раскрываются, сайдпейдж выезжает, диалог появляется — всё с настроенными анимациями.

Настройки анимации элемента:

- **Виды перехода** — список слоёв, на одном элементе может быть несколько (например, fade + сдвиг + масштаб).
- **Изинг** — выбор из стандартных CSS-пресетов (заполняет инпут `cubic-bezier(...)`) либо ручной ввод значений.
- **Длительность** — в миллисекундах.

Настройки применяются **сразу при изменении**, без кнопки «Применить».

Отдельная кнопка открывает **модалку «Параметры»** — полный список всех применённых на макете настроек, с копированием в JSON и в CSS.

### Фаза 3. Поведение макета (`js/mock.js`)

Реализуем интерактив **без анимаций** — только переключение классов/состояний. Анимации подключатся в Фазе 4.

**Сценарии:**
1. Клик по `main-row` (или по шеврону) — раскрывает/схлопывает `expanded-content`, шеврон поворачивается. Состояние — класс `is-open` на строке.
2. Клик по бургеру в сайдбаре — переключает класс `is-collapsed` на сайдбаре (264 ↔ 68 px, подписи скрываются).
3. Клик по кнопке-карандашу в строке ученика — открывает сайдпейдж с именем ученика в заголовке.
4. Крестик / «Отмена» / клик по оверлею / Esc — закрывает сайдпейдж.
5. «Сохранить» в сайдпейдже и «Сохранить изменения» в сабхедере — открывают диалог. «Нет, отменить» / Esc / оверлей — закрывают.
6. Кнопка «+ Добавить ученика» — показывает строку встроенного добавления (`inline-edit-row`) в конце списка. «Крестик» — убирает её, «галочка» — превращает во новую строку ученика с введёнными ФИО (если поля пусты — берём «Новый Ученик»).
7. Кнопка-корзина — удаляет строку ученика из DOM.
8. Состояния: hover — `:hover`, pressed — `:active`, фокус поля — `:focus-visible`, выбранный пункт сайдбара — класс `is-selected`. Конкретные токены для каждого состояния — Приложение H.

**Важно:** удаление и добавление узлов делать **только** через `LS.anim.enter(el)` / `LS.anim.leave(el, done)` — в Фазе 3 это заглушки, которые сразу вызывают колбэк. Так Фаза 4 подключится без переписывания `mock.js`.

**Критерии приёмки**
- Все 8 сценариев работают, консоль чистая.
- Повторное открытие/закрытие сайдпейджа и диалога не ломает фокус и не плодит обработчики.

**Коммит:** `Фаза 3: интерактив макета без анимаций`

### Фаза 4. Движок анимаций (`js/registry.js`, `js/anim.js`, `css/anim.css`)

**4.1. Реестры** (`registry.js`) — заполнить по Приложениям B и C:
- `LS.registry.transitions` — виды перехода;
- `LS.registry.easings` — пресеты изингов;
- `LS.registry.elements` — каталог анимируемых элементов (label, group, список рекомендованных видов перехода).

**4.2. Применение настроек** (`anim.js`):

```js
// Собирает CSS-строку transition для одного элемента из его слоёв
function buildTransition(layers) {
  const parts = [];
  layers.forEach(layer => {
    const def = LS.registry.transitions[layer.type];
    if (!def) return;
    def.props.forEach(prop => {
      parts.push(prop + ' ' + layer.duration + 'ms ' + layer.easing + ' ' + (layer.delay || 0) + 'ms');
    });
  });
  return parts.join(', ');
}

// Применяет настройки ко ВСЕМ элементам с данным data-anim
LS.anim.apply = function (animId) {
  const layers = LS.state.getLayers(animId);
  const css = buildTransition(layers);
  document.querySelectorAll('[data-anim="' + animId + '"]').forEach(el => {
    el.style.transition = css;
  });
};

// Полная переприменялка — вызывается после любого изменения настроек и после вставки новых узлов
LS.anim.applyAll = function () { Object.keys(LS.registry.elements).forEach(LS.anim.apply); };
```

**Ключевое архитектурное решение:** виды перехода используют **независимые CSS-свойства** `translate`, `scale`, `rotate` (а не общий `transform`). Благодаря этому сдвиг, масштаб и поворот можно настроить как отдельные слои с разными длительностями, и они не будут перетирать друг друга.

**4.3. Появление / исчезновение:**

```js
// Появление: ставим "from"-состояние, форсим reflow, снимаем — браузер проигрывает переход
LS.anim.enter = function (el) {
  const layers = LS.state.getLayersFor(el);
  const from = {};
  layers.forEach(l => Object.assign(from, LS.registry.transitions[l.type].from || {}));
  Object.keys(from).forEach(prop => { el.style[prop] = from[prop]; });
  el.style.transition = 'none';
  void el.offsetWidth;                       // принудительный reflow
  el.style.transition = buildTransition(layers);
  Object.keys(from).forEach(prop => { el.style[prop] = ''; });
};

// Исчезновение: ставим "to"-состояние и удаляем узел после максимальной длительности
LS.anim.leave = function (el, done) {
  const layers = LS.state.getLayersFor(el);
  const total = Math.max(0, ...layers.map(l => (l.duration || 0) + (l.delay || 0)));
  const to = {};
  layers.forEach(l => Object.assign(to, LS.registry.transitions[l.type].from || {}));
  el.style.transition = buildTransition(layers);
  Object.keys(to).forEach(prop => { el.style[prop] = to[prop]; });
  setTimeout(done, total);
};
```

**4.4. Раскрытие на авто-высоту** (`collapse`): не `max-height` с выдуманным числом, а grid-приём — контейнер `display: grid; grid-template-rows: 0fr;` в закрытом состоянии и `1fr` в открытом, внутренний враппер `overflow: hidden;`. Анимируемое свойство — `grid-template-rows`. Эти правила живут в `css/anim.css`.

**4.5. Дефолты.** Если у элемента настроек нет — анимаций нет вообще (`transition: none`). Песочница стартует «пустой»: это её смысл — показать разницу.

**Критерии приёмки**
- В консоли `LS.state.setLayers('sidepage', [{type:'slide-right', easing:'cubic-bezier(0.215, 0.61, 0.355, 1)', duration:300, delay:0}]); LS.anim.applyAll();` — сайдпейдж начинает выезжать.
- Несколько слоёв на одном элементе (fade + slide-up) работают одновременно и с разными длительностями.

**Коммит:** `Фаза 4: движок анимаций и реестры`

### Фаза 5. Тулбар и режим выбора (`js/toolbar.js`, `js/inspector.js`, `css/toolbar.css`)

**5.1. Тулбар** — `position: sticky; top: 0; z-index: 1000;` высота 56 px, фон `--layer-1`, нижняя граница `--border-on-layer-1`, тень `--shadow-bottom-xs`. Слева направо:

1. Сегмент-переключатель **«Выбор» / «Просмотр»** (по умолчанию — «Просмотр»).
2. Разделитель.
3. Блок выбранного элемента: название (`.t-md-semibold`) + группа (`.t-sm`, `--content-secondary`); если ничего не выбрано — «Элемент не выбран».
4. Кнопка **«Проиграть»** (повторяет анимацию выбранного элемента) — активна, только когда элемент выбран.
5. Правая часть: кнопка **«Параметры»**, кнопка **«Сбросить всё»**.

Под тулбаром — выдвижная **панель настроек** (часть тулбара, не отдельное окно). Открыта, когда выбран элемент.

**5.2. Режим выбора** (`inspector.js`):
- На `#mock` вешается `class="is-picking"`.
- Перехват кликов на **фазе захвата** на `#mock`: `preventDefault()` + `stopPropagation()`, поиск ближайшего `[data-anim]` через `event.target.closest('[data-anim]')`, выделение.
- Hover: подсветка `outline: 2px solid var(--border-accent-solid); outline-offset: -2px;` + всплывающая метка с названием элемента (абсолютно позиционированный бейдж). Подсветку рисуем через CSS-класс на элементе, **не** меняя его `style.transition`.
- Выделенный элемент: постоянная рамка + класс `is-anim-selected`.
- Esc — снять выделение. Повторный клик по тому же элементу — тоже снимает.
- В режиме «Просмотр» подсветка и перехват выключены полностью, макет работает штатно.

**Критерии приёмки**
- В режиме «Выбор» клик по шеврону не раскрывает строку, а выделяет элемент.
- В режиме «Просмотр» никаких рамок и бейджей нет, все сценарии Фазы 3 работают.
- Тулбар не уезжает при скролле.

**Коммит:** `Фаза 5: тулбар, режимы и выбор элементов`

### Фаза 6. Панель настроек анимации (`js/toolbar.js`)

Панель показывает список слоёв перехода выбранного элемента. Каждый слой — строка:

| Вид перехода | Изинг (пресет) | cubic-bezier | Длительность | Задержка | 🗑 |
|---|---|---|---|---|---|
| `<select>` из `registry.transitions` | `<select>` из `registry.easings` + пункт «Custom» | `<input type="text">` | `<input type="number">` ms | `<input type="number">` ms | кнопка |

Под списком — кнопка **«+ Добавить переход»**.

**Правила:**
1. Любое изменение любого поля → немедленно `LS.state.setLayers(...)` → `LS.anim.apply(animId)` → `LS.state.save()`. Кнопки «Применить» нет.
2. Выбор пресета изинга **заполняет** текстовый инпут значением `cubic-bezier(a, b, c, d)`.
3. Ручное редактирование инпута: парсим `cubic-bezier(a, b, c, d)` (пробелы необязательны, допускаем также голое `a, b, c, d`). Если значение совпало с пресетом — селект встаёт на него; иначе — на «Custom».
4. Невалидный bezier — красная обводка инпута (`--content-negative`), настройка не применяется до исправления, последнее валидное значение сохраняется.
5. Длительность: целое, 0–5000, шаг 10. Пустое/невалидное → не применяем.
6. Добавление второго слоя того же вида запрещено (в `<select>` уже использованные виды — `disabled`).
7. При смене вида перехода в существующем слое изинг и длительность сохраняются.
8. Кнопка «Проиграть» в тулбаре запускает анимацию элемента: для `enter`-подобных видов — `LS.anim.enter()`, для состояний (hover, раскрытие) — временно переключает класс-состояние туда-обратно.

**Критерии приёмки**
- Настроил `sidepage`: slide-right 280 ms ease-out-cubic + fade 200 ms linear → переключился в «Просмотр» → сайдпейдж выезжает и проявляется соответственно.
- Перезагрузка страницы не теряет настройки (localStorage, ключ `lemma-anim-sandbox:v1`).

**Коммит:** `Фаза 6: панель настроек с автоприменением`

### Фаза 7. Модалка «Параметры» (`js/export.js`)

Открывается кнопкой в тулбаре. Модальное окно на весь экран с оверлеем, внутри:

1. Две вкладки: **JSON** и **CSS**.
2. Содержимое — `<pre>` с моноширинным текстом (`Roboto Mono`/`ui-monospace`), с возможностью выделения мышью.
3. Кнопка **«Скопировать»** (использовать `navigator.clipboard.writeText`, фолбэк — `document.execCommand('copy')` через скрытый `<textarea>`, т.к. на `file://` clipboard API может быть недоступен). После копирования — короткий тост «Скопировано».
4. Элементы без настроек в вывод **не попадают**. Если настроек нет вообще — пустое состояние с текстом «Пока ничего не настроено».
5. Закрытие: крестик, Esc, клик по оверлею.

**Формат JSON** — ровно тот, что в §Приложении D.

**Формат CSS:**

```css
/* Таблица — Строка ученика */
[data-anim="student-row"] {

    opacity 200ms cubic-bezier(0.25, 0.46, 0.45, 0.94) 0ms,
    translate 240ms cubic-bezier(0.215, 0.61, 0.355, 1) 0ms;
}
```

Элементы группируются по `data-anim-group`, внутри группы — по порядку из каталога.

**Критерии приёмки**
- CSS из модалки, вставленный в отдельный файл, воспроизводит настройки один в один.
- Копирование работает и при открытии страницы через `file://`.

## Приложение B. Реестр видов перехода (`LS.registry.transitions`)

| `scale` | Масштаб | `scale` | `{ scale: '0.96' }` |
